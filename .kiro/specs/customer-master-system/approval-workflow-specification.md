# 承認ワークフロー詳細仕様

## 概要

本ドキュメントは、法人マスタ管理システムの承認ワークフローに関する詳細仕様を定義する。

## 基本フロー

### 新規法人登録フロー
```
営業担当者が新規法人を登録
↓
自動的に「承認待ち」ステータスになる
↓
部長に申請通知が送信される
↓
部長が承認・却下を判断
↓
承認 → 「承認済み」ステータス → SAP連携 → 申請者に承認通知
却下 → 「却下」ステータス → 申請者に却下通知
```

### 既存法人更新フロー
```
営業担当者が既存法人を更新
↓
変更申請が作成される（元データは「承認済み」のまま）
↓
部長に申請通知が送信される
↓
部長が差分を確認して承認・却下を判断
↓
承認 → 変更内容が本データに反映 → SAP連携 → 申請者に承認通知
却下 → 変更申請が削除 → 申請者に却下通知
```

## 詳細仕様

### 承認期限
- **期限**: 申請から1週間（7営業日）以内
- **期限超過時の処理**: 自動却下
- **期限通知**: 
  - 期限1日前に部長に催促通知
  - 期限当日に部長に催促通知

### 承認権限
- **承認者**: 営業部の部長のみ
- **代理承認**: なし（部長のみが承認可能）
- **承認者変更**: 申請後に部長が変更になった場合は新しい部長が承認

### 編集制御
- **承認待ち法人の他者編集**: エラーで編集不可
- **申請者による再編集**: 可能（申請内容を上書き更新）
- **競合制御方式**: 楽観的ロック（バージョン管理）

### 差分表示
- **対象項目**: 
  - 基本情報（法人名、業界分類、設立年月日など）
  - 住所情報（本社住所、支店・営業所住所）
  - 連絡先情報（電話番号、担当者情報）
  - 口座情報（メイン口座、サブ口座）
  - 手動更新された信用情報（TSR自動更新分は除く）
- **表示方式**: 項目ごとに「変更前」「変更後」を並べて表示
- **新規追加項目**: 「新規追加」として表示
- **削除項目**: 「削除」として表示

### 承認・却下処理
- **承認時**:
  - 承認コメント: 必須入力
  - 承認日時の記録
  - 承認者の記録
  - 変更内容の本データへの反映
  - SAP連携の自動実行
  - 申請者への承認通知

- **却下時**:
  - 却下理由: 必須入力
  - 却下日時の記録
  - 却下者の記録
  - 変更申請の削除
  - 申請者への却下通知（却下理由含む）

### 却下後の処理
- **再申請**: 可能（却下された申請を修正して再提出）
- **却下理由の参照**: 可能
- **却下理由履歴**: 全件保持

### 通知機能
- **通知方法**: システム内通知のみ
- **通知タイミング**:
  - 申請時: 部長に通知
  - 承認・却下時: 申請者に通知
  - 期限前: 部長に催促通知（1日前、当日）
- **通知対象者**:
  - 承認時: 申請者（営業担当者）のみ
  - 却下時: 申請者（営業担当者）のみ

### 履歴管理
- **履歴保持期間**: 永続保持
- **参照権限**:
  - 営業担当者: 部署内の全履歴参照可能
  - 部長: 部署内の全履歴参照可能
  - 情報システム部: 全履歴参照可能

### 一括処理
- **一括承認機能**: なし（個別承認のみ）
- **一括申請機能**: なし（個別申請のみ）

## ステータス遷移

### 法人ステータス
```
下書き → 承認待ち → 承認済み
         ↓
        却下 → 承認待ち（再申請時）
```

### 変更申請ステータス
```
申請中 → 承認済み
       ↓
      却下 → 申請中（再申請時）
```

## エラーハンドリング

### 承認期限超過
- 自動却下処理の実行
- 申請者への期限超過通知
- 却下理由: 「承認期限超過による自動却下」

### 承認者不在
- 代理承認機能なし
- 期限内に承認されない場合は自動却下

### システムエラー
- SAP連携エラー時は管理者に通知
- 通知送信エラー時はログに記録

## 業務ルール

### 承認可能条件
1. 申請者と承認者が同じ部署（営業部）
2. 承認者が部長権限を持つ
3. 申請が承認待ち状態
4. 承認期限内

### 却下可能条件
1. 申請者と承認者が同じ部署（営業部）
2. 承認者が部長権限を持つ
3. 申請が承認待ち状態
4. 却下理由が入力されている

### 再編集可能条件
1. 申請者本人
2. 申請が承認待ち状態
3. 他のユーザーが編集中でない

## データ整合性

### 楽観的ロック
- バージョン番号による競合制御
- 更新時にバージョンチェック
- 競合検出時はエラーメッセージ表示

### トランザクション境界
- 承認処理: 承認 + 本データ更新 + SAP連携を一つのトランザクション
- 却下処理: 却下 + 申請削除を一つのトランザクション
- 通知送信: 別トランザクション（失敗しても本処理は成功）
